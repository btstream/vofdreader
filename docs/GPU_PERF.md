# GPU 资源与性能核验

## 已落实

### 页面纹理生命周期

页面缓存保存 CPU 图片，GPUI 的 sprite atlas 则按 `ImageId` 独立保存 GPU 条目。移除 `Arc<RenderImage>` 不等于移除 atlas 条目。

- 页面图片进入缓存时，登记其 ID 和资源所有权。
- 每次 Reader 渲染前，用页面缓存和当前单页图片计算存活集合；对不再使用的图片调用当前窗口的 `Window::drop_image()`。
- 高密度替代、LRU 淘汰、切换文档和打开失败均走相同清理路径。
- 单页还在显示的旧图片即使已不在缓存中，也不提前释放。
- Reader 销毁时清理剩余资源；不依赖 `Arc::strong_count` 猜测显示状态。
- 缩略图（含连续视图中的低清占位）为内存 `RenderImage`，登记进同一存活集合；切换文档或清理缩略图后，下一帧调用 `drop_image` 释放 atlas。

### 绘制与上传控制

- 页面使用稳定的 `RenderImage` ID；只有成功绘制时才记录首次使用，普通重绘不重新创建图片。
- 页面绘制先检查当前裁剪范围；完全离屏的缓冲页不提交图片、不因预取而提前上传纹理。
- 点阵位置按画布尺寸缓存，不再逐帧创建坐标数组；绘制时跳过不透明页面完全遮住的点，保留圆角周围和露出的背景。
- 一个 1000×700 逻辑像素的测试画布、800×680 页面案例中，背景点图元从 1053 个减少到 247 个。这是图元数量，不是 draw call 数或 GPU 降幅。
- 默认保留原有页面阴影、窗口阴影和圆角。没有改变 opt-level，也没有固定降低刷新率；高倍分块路径见下文。

## P2：可见区域分块

- 单页和连续视图均接入高清块叠层，搜索与选择仍在其上方。目标密度超过 192 DPI，或目标整页超过 400 万像素时启用；普通小页面保留整页路径。
- 整页预览最高 96 DPI，高清块按屏幕密度取 24 DPI 桶，默认最高 768 DPI；可在设置中改为更高的自定义上限。大/HiDPI 视口仍按工作集预算限制密度。
- 512×512 设备像素网格，边缘块裁短；2px 采样 gutter 不重复显示。相邻内容采用同一网格边界，没有内部圆角。
- 在 GPUI prepaint 中以页面实际边界与当前 content mask 求交，含横向裁剪；优先请求相交的块，再空闲预取外围一圈。滚动中保留预览，停止后串行补块，不预渲染全页高清网格。附近页面低清预览与邻块预取策略见 [性能记录](PERF.md#空闲预取)。
- 复用同一解析树；区域 API 的全局缩放和平移保留页面坐标。另加 16px 内部光栅留边再裁剪，减少画布边缘对抗锯齿的影响。
- 返回时检查文档代次和最新可见请求，过期结果不入缓存。换文档清空块缓存，旧任务返回前不占用第二个块任务槽。
- 默认 CPU 渲染结果缓存预算为 256 MiB（原为 128 MiB），拆成 192 MiB 整页、64 MiB 分块；整页数量上限由 8 提到 32，块缓存按最近可见顺序淘汰。密度计算仍以原有 96/32 MiB 活动工作集为基准，新增空间优先保留历史结果，不自动提高 DPI。整页原有当前图保护规则仍适用，任务缓冲、显示中旧图与解析树不计入缓存预算，因此这**不是进程内存硬上限**。
- 块图片纳入同一 GPU Resources 存活集合，淘汰/换文档后的下一次 Reader 渲染清理 atlas。导出 PNG 仍走整页路径。

验证：网格边缘、横向裁剪、非法范围、共享接缝边界及面积覆盖测试；合成对齐色块在跨网格裁剪时与整页逐字节一致。带文字/Pattern 的合成文档在 96/216/384 DPI 比较裁剪内部，允许抗锯齿舍入差异（单通道峰值≤32，累计差异小于像素数），不宣称复杂页面逐像素相同。

显式语料测试已通过 40 份 / 118 页 / 354 个 768 DPI 区域。这验证区域渲染无错误，不等于全页像素一致或桌面接缝已人工验收；当前环境仍缺少可控的可见桌面滚动/缩放对照。

```bash
cargo test -p ofd-core --test regions -- --ignored --nocapture
```

## 诊断与 A/B 开关

```bash
OFD_GPU_DIAGNOSTICS=1 ./target/release/ofd-app resources/y.ofd 2> /tmp/opencode/gpu.log

# 分别对照，不要同时更改多个变量
OFD_GPU_DIAGNOSTICS=1 OFD_GPU_DISABLE_DOTS=1 ./target/release/ofd-app resources/y.ofd
OFD_GPU_DIAGNOSTICS=1 OFD_GPU_DISABLE_PAGE_SHADOWS=1 ./target/release/ofd-app resources/y.ofd
```

开关默认关闭；阴影开关仅用于页面，不修改约定的窗口装饰。诊断不使用刷新定时器，不为了输出日志额外重绘窗口。

日志含义：

| 字段 | 含义 |
| --- | --- |
| `frames` | ReaderApp::render 调用次数，不是显卡实际呈现帧数 |
| `page_draws` | 通过裁剪检查且提交成功的页面图片绘制次数 |
| `images_created` | 纳入管理的不同页面图片数量 |
| `first_uses` / `first_use_mib` | 页面图片首次成功提交的次数 / RGBA 字节；用于发现重复创建和首次上传压力 |
| `releases` | 已使用页面图片的 atlas 清理调用数量 |
| `page_resident_mib` | 已提交且未清理的页面 RGBA 估计值，不是驱动显存读数 |
| `cpu_cache_mib` | 应用页面缓存字节数 |
| `dot_quads` / `dot_layouts` | 背景点累计绘制数量 / 几何重建次数 |

首次使用计数不是硬件 DMA 计数，无法捕获驱动/设备重置导致的重新上传。页面统计不含缩略图、字体图集、交换链、命令缓冲和图集分配余量；因此不能将其当作整进程显存上限。

## Linux 进程级采样

无需安装工具或修改系统权限，可读取驱动提供的 `/proc/PID/fdinfo`：

```bash
python3 scripts/profile-gpu.py --pid "$(pgrep -n ofd-app)" --duration 30 > /tmp/opencode/gpu-samples.jsonl
python3 scripts/profile-gpu.py --self-test
```

采样器按 DRM 客户端去重，输出各 engine 的时间增量/墙钟时间及驱动原始内存字段。结果是该进程的 engine 活跃时间，不是整机 GPU 百分比；不同 engine 不应简单相加。驱动内存字段也可能包含共享分配，不能相加为独占显存。

没有权限或驱动不支持时会提示不可用并输出空指标，不把 GPU 频率冒充占用率。本机 Intel Iris Xe / i915 已成功采到 render/copy engine 及 system 内存字段。

## 核验与比较方法

- 常规测试覆盖同一图片 100 次重绘只有一次首次使用、当前显示图片保护、连续 100 次文档资源清理、未绘制预取图片、失败清理重试及背景点裁剪。
- 使用 GPUI 的 HeadlessAtlas 验证清理后原图片 ID 的 atlas 条目确实不存在，而不仅是减少计数。
- Release 实机启动已通过；一轮日志中 10 次页面绘制只有 1 次首次使用。实机也观察到旧密度图片被清理后再使用新图片的正常过程。
- 当前 A/B 试跑中的窗口交互/重绘数量不一致，**不据此报告 GPU 降幅**。

正式比较需固定窗口物理尺寸、屏幕缩放、文件、滚动路径、缩放次数和采样时长；分别测空白窗口、文件静止、滚动及缩放/切换文档。静止时首先确认帧数不持续增长；反复切换后确认清理计数增长，页面驻留估计不随历史文档累积。再对照进程 engine 时间与驱动内存，不将 KWin 或其他应用的 GPU 使用归因于阅读器。

### 固定重绘阴影对照

```bash
python3 scripts/bench-gpu-shadows.py --file resources/y.ofd \
  --output /tmp/opencode/gpu-shadow-comparison
```

脚本交替顺序运行三组默认/关闭页面阴影的相同文件，预热后用 `OFD_GPU_BENCH_FRAMES=180` 驱动固定数量的重绘请求，采样只取 begin/end 内完整区间。此开关只用于测试，正常会话没有重绘定时器。请将窗口留在可见桌面，勿最小化/切换文件或移动缩放窗口；仅当页面已实际绘制、纹理工作集稳定、实际 Reader 帧数达到请求的 90% 时接受数据。还须人工确认 A/B 帧数与页面绘制次数匹配；脚本不会自动声称性能提升。

本轮桌面环境六次试跑都只有 2 次 Reader 渲染、0 次页面绘制；零 engine 读数**无效**，不是“阴影无成本”。已增加预热超时和实际绘制检查，今后此类试跑输出 `valid: false`。P1 的测量结论仍待可见桌面复测，保持默认阴影，不以未测收益为由改动设计。

#### 2026-11-05 实测：页面阴影九宫格试验（已撤回）

环境：Intel Iris Xe（TigerLake GT2），4K 外接屏缩放 1.75，`resources/y.ofd` 连续视图，每组 180 帧、约 60 fps，同一时段交替运行；每帧 GPU 时间 = render 引擎占用 × 时长 / 帧数。

| 构建 | 默认阴影 | 关闭阴影 | 阴影开销 |
| --- | --- | --- | --- |
| GPUI `shadow_lg()` | 7.71 ms | 6.49 ms | ≈1.2 ms（约 16%） |
| CPU 九宫格（试验，已撤回） | 6.52 ms | 6.37 ms | ≈0.15 ms |

- GPUI 的阴影着色器对“元素 + 3σ 外边距”整块矩形逐像素计算（含被页面遮住的内部），整页卡片在 4K 下每帧数百万像素、两层。试验改为按屏幕缩放由 CPU 一次生成 4 个角与 4 条 1 像素边条（只覆盖卡片外侧），GPU 每帧只采样小纹理。
- 结论：y.ofd（157% 缩放、分块模式）每帧约省 1.2 ms；intro-数科.ofd（100%、无分块）上 GPUI 阴影本身几乎无开销，新旧持平。整体收益有限，**已撤回，页面阴影仍用 GPUI `shadow_lg()`**。
- 试验时外观与 `shadow_lg()` 一致：单元测试按 GPUI `fs_shadow` 算法逐点对比，卡片外 alpha 差 < 2/255；实机截图整窗峰值差 8/255。
- 同时测得：首轮新版本试跑曾出现 11.9 ms/帧、58 fps，紧接着重跑恢复为 6.5 ms——单次结果受桌面其他负载影响，比较须交替多轮并在同一时段完成。
- 其余约 6.4 ms/帧为整窗 4K 合成（页面纹理、窗口装饰、界面），尚未拆分。
- 后台任务（预取页、预取块、缩略图）完成时只在结果可见时重绘整窗；诊断日志新增 `background_jobs` / `background_redraws`。3 页的 y.ofd 上仅减少 4 次重绘，主要对多页文档的预取阶段有意义。

#### 每帧开销分项（intro-数科.ofd 第 17 页，100%，浮动窗口）

测量时临时加入了 `OFD_GPU_DISABLE_WINDOW_SHADOW`、`OFD_GPU_DISABLE_PAGE_IMAGE`（跳过页面纹理）、`OFD_GPU_DISABLE_CHROME`（标题栏/工具栏/状态栏保留布局但不绘制）三个开关，结论记录后**已移除**；现存的只有 `OFD_GPU_DISABLE_PAGE_SHADOWS` 与 `OFD_GPU_DISABLE_DOTS`。每个变体 3 轮、轮换顺序、各 180 帧：

| 变体 | 每帧 GPU | 相对完整 |
| --- | --- | --- |
| 完整 | 6.84 ms | — |
| 关窗口阴影 | 5.90 ms | −0.95 ms |
| 关页面纹理 | 6.13 ms | −0.72 ms |
| 关标题栏/工具栏/状态栏 | 6.46 ms | −0.38 ms |
| 关页面阴影（测量时为九宫格试验版） | 6.78 ms | −0.07 ms |
| 以上全关 | 5.00 ms | −1.84 ms |

- 窗口阴影（`vendor/gpui-component/src/window_border.rs`，整窗 blur 5px）是最大的单项，与页面阴影同样是对整窗面积逐像素计算；平铺/最大化时不绘制。
- 结论：可单独关闭的部分合计约 1.8 ms/帧，总体收益有限，暂不针对窗口阴影或固定开销做改动。
- 全关后仍有约 5.0 ms/帧：只剩窗口、阅读区和页面卡片的背景/边框/圆角四边形，属于整窗 4K 的固定开销，需进一步拆分（重叠的全窗背景层）。
- i915 频率 100–1300 MHz，测量期间在 0（RC6 休眠）与约 1150–1300 MHz 之间突发切换；毫秒数为 engine 忙碌时间折算，适合相互比较，不等于固定频率下的耗时。
