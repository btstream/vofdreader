# 位图内存预算

## 保证范围

设置中的“渲染位图预算”主要控制**阅读器可追踪的输出位图资源**：

| 计入主账本 | 不计入主账本（部分另有缓存限制） |
|---|---|
| 整页位图缓存 | 字体数据与字形轮廓 |
| 分块位图缓存 | 已解析页面与绘制指令 |
| 当前屏幕显示的位图 | 解码后的内嵌图片 |
| 登记表仍持有的整页/分块像素 | 缩略图 |
| 正在渲染任务的预留像素 | GPU 纹理（atlas） |
| | 光栅器内部临时图层 |
| | ZIP 条目缓存（独立约 16 MiB） |
| | 整个进程的其他开销 |

**它不是进程 RSS 上限。**系统监视器显示的数值会高于这里的预算，因为它还包含
上面右列以及其他运行时开销。

## 两个账目

```text
resident    缓存、屏幕与资源登记表仍持有的整页/分块位图
reserved    在途任务，以及已完成但等待下一帧替换的单页结果
```

预算拆分（`BudgetLimits::split`）：

| 项目 | 取值 |
|---|---|
| resident 上限 | 设置值 |
| reserved 上限 | 设置值的 1/4 |

`1/4` 是当前保守的并发输出额度策略，尚无实机峰值测量来证明它是最佳比例。
单个任务也必须放进该池，因此即使驻留池仍有空间，大页面也可能降级。

两个池的配置额度相加为设置值的 **1.25 倍**，这不是实际内存峰值保证。
调小设置时，旧驻留资源与旧任务的额度还可能超过新上限；光栅器内部图层、
缩略图、分配器开销及框架内部引用也不在这个总数内。

## 随预算缩放的辅助缓存

桌面程序还会将设置应用到以下独立的保留策略；它们不是主账本的剩余额度：

| 资源 | 保留策略 | 设置为 64 MiB 时 |
|---|---|---|
| 全部缩略图输出 | 设置值的 1/8，最多 64 MiB | 8 MiB |
| 解码原图 LRU | 设置值的 1/4，最多 64 MiB | 16 MiB |
| 解析页主要内容估算 | 设置值的 1/2，最多 128 MiB | 32 MiB |
| 解析页数量 | 用户页数与 `max(1, 设置 MiB / 16)` 的较小值 | 最多 4 页 |

缩略图按总槽位数分配每页像素额度，在 1–48 DPI 内选择可容纳的密度，并限制最长边
为 512 像素；实际结果还要通过字节检查。调小或调大其额度会换批重建，不改变侧栏页码槽位。

解码缓存只淘汰最旧项。大于整个池的原图仍需解码才能绘制，但不会插入缓存或清空其他有效项。
解析页权重计入主要绘制操作、路径和图像内容，同页共享资源去重、跨页保守重复计费；这不是
完整的堆测量，不包括全部容器容量、渐变/字体缓存等开销。过大页面可绘制，但不保留在解析缓存。
同页的在途绘制通过弱引用共享已构建资源，避免超过保留额度时每个并行分块都重复解码；
最后一个绘制者退出后，弱引用不会延长像素或路径的生命周期。

设置变更立即更新原子限制，空闲缓存立即收缩；繁忙缓存下一次访问/当前解码结束时应用新额度。
在途绘制仍可能通过 `Arc` 保留已经淘汰的资源。因此这些保留额度不可直接相加当作 RSS 保证。

## 滚动预取与分配器

预取选择出的整组可容纳页面都参与淘汰保护，而不只是本次插入的页面。
连续视图为了布局构建的缓冲行可以复用图片，但不能反复触碰 LRU、挤掉当前计划的邻页。
离开计划的迟到结果不进入缓存，后台页也不能因所有项受保护而突破页面字节额度。

Linux/glibc 桌面程序在线程池及字体加载之前，默认将 malloc arena 数限制为 2，
避免多个后台线程各自保留大像素分配的高水位。设置只影响当前进程，不修改系统配置；
显式的 `MALLOC_ARENA_MAX` 或 `GLIBC_TUNABLES` 中的 `glibc.malloc.arena_max` 优先。
其他平台不应用此策略，也不加入周期性的 `malloc_trim`。该优化不提供 RSS 硬上限。

## 计费去重

位图按 GPUI 的 `ImageId` 计费。同一张图即使同时在整页缓存、分块缓存、
当前画面和图片登记表中，也只计一次。

从缓存删除时，只有确认没有任何缓存、当前画面或资源登记表继续引用该 `ImageId`，
才从账本扣除。登记表要到窗口帧成功释放该图片后才撤销所有权；释放失败继续计费。
失效、关闭文档、替换画面和替换同键缓存也遵循这个规则。

## 启动前预留

整页、连续页/预取页与分块任务在开始光栅化前预留估算像素：

- 整页按页面尺寸、DPI 计算，每边向上取整加一像素。
- 分块按采样区域尺寸计算；旋转时额外预留一份像素，覆盖已知的旋转复制缓冲。
- 整页旋转同样预留输入与输出两份像素，但不估算光栅器内部图层。
- 预留失败时不启动任务。

预留失败有两种原因：

| 原因 | 行为 |
|---|---|
| 单个任务超过 reserved 池容量 | 按固定容量降低 DPI；最低档仍不合适时当前页提示错误 |
| 在途预留池已满 | 本轮不启动，等待已运行任务返回 |

临时占用不会改变目标 DPI，也不会记成页面错误。所有物理任务完成时（包括旧文档、
旧旋转任务）都会唤醒当前视图，下一帧在资源对账后重新检查调度。
后台页若连受保护的驻留工作集都无法共存，会在光栅化之前跳过，而不是完成后反复被拒。

结果完成不等于驻留接纳。过期或离开计划的结果只释放预留，不登记驻留图片；
缓存拒绝的结果不得登记到资源表或显示。

## 调小预算

设置变化立即更新账本上限，并主动收缩：

1. 先淘汰预取分块。
2. 再淘汰离屏整页位图，最旧的先走。
3. 有界扫描离屏页；多个受保护页仍超限时也必须返回，不能循环等待额度。
4. 清理不再符合新密度计划的旧缓存；单页旧画面保留到替换结果到达。

仍符合计划的在屏分块不作为“预取”淘汰。旧任务保留原来的预留，过大结果返回后
丢弃并重新规划。旧资源可能暂时超出新上限；最低档也放不下、或窗口资源释放失败时，
不能保证自动收敛到新额度。

## 预算不足时的降级

页面无法按目标 DPI 预留时，按 24 DPI 一档下调，直到可预留：

| 场景 | 最低 DPI | 行为 |
|---|---|---|
| 单页主视图 | 目标 DPI 与 96 的较小值 | 显示降级后的画面 |
| 连续页与预取 | 目标 DPI 与 48 的较小值 | 能显示即可，返回后按需提升 |
| 高清分块 | 不降级 | 预留失败则跳过该分块 |

密度根据当前页面尺寸、缩放、旋转和预算容量重新计算，不保留跨页面的全局上限。
连续页的缓存检查、去重、失败记录与实际渲染统一使用解析后的 DPI，避免重复渲染
同一档低清图片。释放临时预留不会触发无意义的升降档；提高预算后可以恢复清晰度。

只有在最低档也无法预留时，才显示“页面位图超过缓存预算”。

## 单页画面替换

完成的前台结果保留原预留，最多等待一个单页替换槽。下一窗口帧再次检查文档代际、
请求标识、当前页与新预算；过期结果直接丢弃。有效结果在同一帧撤销旧画面与同页缓存，
释放登记表所有权，再尝试接纳与显示新图片，最后释放预留。

接纳最多尝试两次：一次缓存淘汰后，再做一次资源对账，不无限重试。
接纳失败显示错误，绝不显示账本拒绝的图片。文档失效或关闭会取消待替换结果的预留。

## 诊断

设置 `OFD_GPU_DIAGNOSTICS=1` 时，每帧输出一行：

```text
[budget] resident=.. reserved_in_flight=.. page_cache=.. tiles=.. jobs=.. limit_resident=.. limit_in_flight=..
```

这里的数值是阅读器计费值，不是操作系统内存统计。

设置 `OFD_SCROLL_BENCH_STEPS=30` 可显式启动滚动回归工作负载（默认没有额外定时器）：
连续模式打开文档后等待 3 秒，回到首页，每 200ms 向下滚动 1000px 共 30 步，
再反向同样步数，最后等待 5 秒记录账本、缩略图与 Linux RSS。它会改变阅读位置，
建议使用独立配置目录。复测条件和实测数据见 [SCROLL_MEMORY_CHECK.md](SCROLL_MEMORY_CHECK.md)。

## 已知边界

- 单个任务可能大于预留池，而不是只有大于设置值才会被拒绝。
- 光栅器内部的临时分配无法精确预知，只能通过预留估算覆盖主要部分。
- GPU atlas 与 CPU 位图分别统计，设置不限制显存。
- 缩略图和源图片/解析资源使用独立保留策略，不参与输出账本。
- 完整原图解码、在途页面、字体缓存、图层与分配器碎片仍会使 RSS 超过这些额度。
- 单元测试不代替低预算、大页面、渲染中调预算与连续滚动的 GUI 验收。
