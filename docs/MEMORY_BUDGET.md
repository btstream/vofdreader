# 位图内存预算

## 保证范围

设置中的“内存缓存”控制的是**阅读器可追踪的位图资源**：

| 计入 | 不计入 |
|---|---|
| 整页位图缓存 | 字体数据与字形轮廓 |
| 分块位图缓存 | 已解析页面与绘制指令 |
| 当前屏幕显示的位图 | 解码后的内嵌图片 |
| 正在渲染任务的预留像素 | GPU 纹理（atlas） |
| | 光栅器内部临时图层 |
| | ZIP 条目缓存（独立约 16 MiB） |
| | 整个进程的其他开销 |

**它不是进程 RSS 上限。**系统监视器显示的数值会高于这里的预算，因为它还包含
上面右列以及其他运行时开销。

## 三个账目

```text
resident    缓存与屏幕实际保留的位图
reserved    正在渲染、尚未返回的位图预留
```

预算拆分（`BudgetLimits::split`）：

| 项目 | 取值 |
|---|---|
| resident 上限 | 设置值 |
| reserved 上限 | 设置值的 1/4 |

因此可追踪位图在最坏情况下为设置值的 **1.25 倍**：保留部分仍在设置值内，
超出的部分是尚未返回的在途像素。

## 计费去重

位图按 GPUI 的 `ImageId` 计费。同一张图即使同时在整页缓存、分块缓存、
当前画面和图片登记表中，也只计一次。

从缓存删除时，只有确认没有任何缓存或当前画面继续引用该 `ImageId`，
才从账本扣除。否则内存仍被持有，账面不应提前减少。

## 启动前预留

整页、连续页/预取页与分块任务在开始光栅化前预留估算像素：

- 整页按页面尺寸、DPI 与旋转计算，每边向上取整加一像素。
- 分块按采样区域尺寸计算。
- 预留失败时不启动任务。

预留失败有两种原因：

| 原因 | 行为 |
|---|---|
| 单个位图大于 resident 上限 | 当前页显示错误提示，不重试同一请求 |
| 在途预留池已满 | 本轮不启动，等待已运行任务返回 |

## 调小预算

设置变化立即更新账本上限，并主动收缩：

1. 先淘汰预取分块。
2. 再淘汰离屏整页位图，最旧的先走。
3. 当前页与连续视图在屏页面不动。

在途任务保留自己的预留，返回后才结算。受保护的在屏内容可能短暂超过新上限，
这是有意为之：立即清空会造成空白或闪烁。

## 预算不足时的降级

页面无法按目标 DPI 预留时，按 24 DPI 一档下调，直到可预留：

| 场景 | 最低 DPI | 行为 |
|---|---|---|
| 单页主视图 | 目标 DPI 与 96 的较小值 | 显示降级后的画面 |
| 连续页与预取 | 目标 DPI 与 48 的较小值 | 能显示即可，返回后按需提升 |
| 高清分块 | 不降级 | 预留失败则跳过该分块 |

单页降级后会记住允许的密度，避免每帧重复请求已被拒绝的目标 DPI 而反复重渲染。

只有在最低档也无法预留时，才显示“页面位图超过缓存预算”。

## 诊断

设置 `OFD_GPU_DIAGNOSTICS=1` 时，每帧输出一行：

```text
[budget] resident=.. reserved_in_flight=.. page_cache=.. tiles=.. jobs=.. limit_resident=.. limit_in_flight=..
```

这里的数值是阅读器计费值，不是操作系统内存统计。

## 已知边界

- 单张高清页面可能大于设置值，此时当前页会显示“页面位图超过缓存预算”。
- 光栅器内部的临时分配无法精确预知，只能通过预留估算覆盖主要部分。
- GPU atlas 与 CPU 位图分别统计，设置不限制显存。
- 缩略图目前不参与该账本。
