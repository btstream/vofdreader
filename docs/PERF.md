# 渲染性能与执行记录

## 直绘后端（DisplayList → tiny-skia，跳过 SVG）

屏幕、分块与 PNG 光栅默认不再生成 SVG 文本、也不再经 usvg 解析：`crates/ofd-core/src/render/raster.rs` 把 DisplayList 准备成带页面坐标包围盒的扁平绘制指令（组变换提前合成，仅透明组保留为图层），按页缓存（沿用 `tree_cache` 上限）。SVG 导出不变。

- **分块裁剪**：每条指令与当前像素区域（含 2px 抗锯齿余量）求交，分块只画命中的内容；resvg 本身不做节点裁剪。
- **图片只解码一次**：页面准备时解码，按内容哈希跨页共享（256 MiB 上限）；resvg 每次 render 都会重新解码 JPEG/PNG。
- **系统字体文本**：OFD 已逐字定位，不做 shaping；选字与回退顺序复刻 usvg 默认实现，字形轮廓按 (face, char) 缓存，内嵌字形按轮廓去重。
- **语义对齐**：同一 tiny-skia 光栅器；透明度按四位小数 + usvg 的 `×255+0.5` 取整；线宽 <0.00005 视为无描边；虚线奇数项复制、负值/零和忽略；零面积路径不填充；图片 Bicubic；页面尺寸按 usvg 的 f32 毫米换算取整。SVG 印章图片仍交给 resvg 渲染（准备时解析一次）。
- `parse_page` 改为不持锁解析，为后续并发分块做准备。
- A/B：`OFD_RENDER_BACKEND=svg` 切回旧路径；`PageRenderer::with_backend()` 供测试使用。

像素对照（`cargo run --release -p ofd-core --example compare_backends -- DPI [DIFF_DIR] FILE...`），本地语料 96 页，96 与 192 DPI：全部尺寸一致，全部满足“单通道差 >32 的像素 <1%”。已知差异：`z.ofd` 第 4 页泰米尔文回退文本（0.24%），旧路径经 rustybuzz shaping 插入“◌”占位圈，新路径逐字取字形；两者都不是文档原意（该处缺内嵌字形）。其余峰值差多为个别边缘像素。常规测试 `direct_backend_matches_svg_backend` 覆盖填充/奇偶规则/弧/虚线/透明度。

Release、本机一次采样（同一台机器、负载不同，仅看量级）：

| 样本 | 指标 | SVG 路径 | 直绘 |
| --- | --- | --- | --- |
| containsJPEG p1 | 384 DPI 全网格 63 块 | 2338.99 ms（中位 35.13 ms/块） | 202.94 ms（中位 0.34 ms/块） |
| containsJPEG p1 | 768 DPI 3×2 视口 | 199.95 ms | 9.86 ms |
| containsJPEG | 96 DPI 整页（热） | ≈44 ms | ≈11 ms |
| y.ofd p1 | 168 DPI 首次光栅（冷） | 219.45 ms | 75.94 ms |
| y.ofd p1 | 768 DPI 全网格 208 块 | 627.09 ms | 281.45 ms |
| y.ofd p1 | 384 DPI 整页（热，同进程交替） | ≈120 ms | ≈120 ms |

整页热光栅没有提升：成本在像素填充本身，两条路径相同。

### 并发分块与内存缩略图

- **分块并发**：原来的单槽 `tile_busy` 改为在途表 `tile_jobs`，最多 `tiles::concurrency()` 个任务并行（核数一半，限制在 1–4）。按原有优先级先填可见块；附近页预取和外围块仍在没有分块运行时才开始。预算检查计入在途块字节。页面渲染、缩略图、GPU 基准等原本因 `tile_busy` 让路的路径，语义不变（有任一分块在跑即让路）。
- **同页只构建一次**：`PageRenderer` 每页一个构建闸门，并行分块同时命中未缓存页时只准备一次；其他页的任务不等待。字体缓存锁仍在页面准备期间持有，不同页的并发准备会排队（当前调度下很少发生）。
- **缩略图**：不再 `render_png` → 写临时文件 → `img(path)` 解码，改为 `rasterize_preview` 直接生成 BGRA `RenderImage`，纳入 GPU 资源存活集合（换文档即释放 atlas），移除 `RetainAllImageCache`。`rasterize_preview` 复用已缓存页，但未命中时构建的页面不入缓存，80 张缩略图不再挤掉正在阅读的页面。设置页“清理缓存”丢弃内存缩略图并重新生成，同时删除旧版本留在临时目录的 `thumb-*.png`。

Release、本机一次采样，页面已准备，`bench` 的全网格串行 vs 4 线程：

| 样本 | 384 DPI 串行 → 4 线程 | 768 DPI 串行 → 4 线程 |
| --- | --- | --- |
| containsJPEG p1 | 249.72 → 58.19 ms | 874.11 → 265.30 ms |
| y.ofd p1 | 155.37 → 67.52 ms | 372.11 → 87.72 ms |
| intro-数科 p1 | 38.05 → 11.54 ms | 126.44 → 37.62 ms |

这是 core 级吞吐，不是桌面上“滚动停止到清晰”的实测延迟；后者仍需在可见桌面复测。



GPU 纹理清理、绘制统计和进程级采样见 [GPU 性能核验](GPU_PERF.md)。页面 CPU 缓存预算不等于 GPU atlas 分配量；当前已增加显式纹理生命周期管理。

## 当前缓存策略与配置接口

为减少往返滚动的重复光栅化，默认策略已调整为：

| 缓存 | 原值 | 当前默认值 |
| --- | --- | --- |
| 整页位图 | 96 MiB / 8 张 | 192 MiB / 32 张 |
| 高清分块 | 32 MiB | 64 MiB |
| 解析后的页面树 | 4 页 | 桌面阅读器 12 页 |

缓存仍按需填充、命中更新 LRU、超预算淘汰，切换文档仍清空，不预先分配全部容量或保留所有历史文档。连续视图的活动工作集与分块密度预算保持原值，增加容量用于延长已渲染结果的保留时间，而非提高 DPI。

`crates/ofd-app/src/cache_config.rs` 的 `CacheConfig::new(total_mib, page_limit, parsed_page_limit)` 由设置窗口写入，通过 `ReaderApp::new` 和设置动作注入。统一校验范围分别为 64–2048 MiB、4–256 张整页、1–64 页解析树；总位图预算按 3:1 分配给整页和分块。核心提供 `PageRenderer::with_tree_cache_limit`，未指定时核心默认仍为 4 页，不改变 CLI 等调用方行为。配置保存到用户配置目录的 `vofdreader/settings.json`；解析页缓存上限在下次打开文档时应用，其他缓存参数在后续淘汰/请求中生效。

这些是缓存保留预算，不是进程总内存上限；字体、解析树、临时渲染缓冲、受保护的当前图及 GPU atlas 另计。更大的缓存也可能保留更多 GPU 纹理。测试覆盖参数边界、增加容量时活动密度预算不变，以及解析树命中复用、LRU 淘汰与禁用缓存；尚未报告整机内存或重复渲染降幅。

### 空闲预取

- 默认预渲染当前页前后各 2 页；连续模式以实际可见页范围为中心向两侧扩展，单页模式以当前页为中心。预览最高 96 DPI，按页数和预算降低，优先距离近的页面；页数上限不足时缩小预取范围。
- 所有可见页预览、所有可见高清块就绪后，再预取附近页，最后补可见块外围 1 圈（含对角邻块），不生成整页高清网格。
- 邻块全局去重并裁到页面边界，投机块数量最多占分块缓存预算的四分之一，且扣除可见块估计工作集后再限额。预取不淘汰当前可见块；预取图像只保存 CPU 结果，实际可见后才提交 GPU 图片绘制。
- 沿用串行前景任务槽和滚动防抖；滚动、密度防抖和前景渲染期间不启动新预取，不取消已在运行的一个任务。完成时重新检查文档代次和当前范围，过期结果丢弃。
- 单页翻页时，即使预取预览低于目标 DPI，也立即复用显示，然后按需补清晰版本；不会因为预取密度较低而完全忽略缓存。
- `CacheConfig::with_prefetch(pages, tile_ring)` 已接设置窗口；默认 `(2, 1)`，允许设 `0` 分别关闭，对应上限为每侧 4 页 / 外围 2 圈。修改后立即影响后续预取调度。

测试覆盖文档首尾/空范围、关闭预取、邻块去重/边界、可见块跨页优先级、预算限额、预取转可见时缓存 Key 复用；未据此报告桌面滚动延迟的具体降幅。

下文的 128 MiB / 8 张描述属于历史阶段记录，以本节当前默认值为准。

## 连续视图滚动优化

已确认并处理的瓶颈：

- 原先每个滚动帧遍历所有页面、克隆所有缓存位图，并重建整份文档的页面控件；滚动偏移还从文档开头逐页扫描。
- 原先可见/预取页全部使用目标 DPI，高缩放时工作集超过 128 MiB，可能出现缓存淘汰后立即重新光栅化。
- 原先快速经过的页面都会提交后台任务，并与缩略图任务争用 CPU。

当前策略：

1. 缓存页尺寸及前缀偏移，仅尺寸、窗口宽度、侧栏或缩放改变时重建；二分查找可见页。
2. 只构建可见页及前后一个缓冲页，上下占位保持原始滚动高度；只触碰这些页的位图/LRU。
3. 滚轮与连续视图键盘滚动停止 160ms 后才提交新光栅任务；滚动中复用已有位图或缩略图。单页滚轮翻页也合并为最终页请求。
4. 连续视图最多一个在途页面任务，每次完成后按最新视口重新选择任务，不积压滚过页面；不保留已经离开视口的完成帧。
5. 可见页优先；按工作集预算限制 DPI，预取页最高 96 DPI，并独立限制预取内存。允许缓存数量覆盖当前窗口，但维持 128 MiB 字节预算；清理被更清晰位图替代的旧密度。
6. 缩略图在滚动或前景页面渲染时暂停提交，已经在途的一张允许完成；搜索高亮的 XML/文字解析延迟到滚动停止。

回归测试覆盖混合纸张尺寸、虚拟占位总高度、万页可见窗口、布局缓存复用、DPI 字节预算及滚动期间任务准入。

手动几何微基准（Release，本机一次采样，**不是整机 CPU 或绘制耗时**）：10,000 页 / 2,000 个滚动位置，线性扫描 16.94ms，缓存查询 85.43µs，最多 4 个活动页面行。

```bash
cargo test --release -p ofd-app scrolling_geometry_benchmark -- --ignored --nocapture
```

未改变编译 opt-level。真实滚轮下的 CPU 百分比仍需在用户桌面复测；微基准不替代交互性能测量。

本文件对应“先分析、后按 P0–P5 执行”的计划。所有数字均为 **Release**、Linux Wayland、本地真实发票（1 页，210×140 mm）；100 页样本由该发票复制页面生成，仅用于本地测量，不入库。

## 基准命令

```bash
cargo run --release -p ofd-core --example bench -- <file.ofd> [page] [dpi]
```

分阶段输出：打开、页面尺寸、DisplayList、导出/内部 SVG、字体库、冷/热光栅化、PNG 编码。含内嵌字体的页面会把文字转成路径，内部 SVG 与光栅成本会高于纯系统字体页面。

当前屏幕与导出共用字形路径，不再输出无用的 `@font-face`。以下 P0 数据为此前阶段的记录，不能直接作为完成字体轮廓支持后的性能数值。字体报告按页面缓存，首次请求需核验字形，后续缩放不重复核验。

字体完善后 `y.ofd` 第 2 页（Release、本机一次采样）：DisplayList 7.33 ms，内部 SVG 158.81 ms / 2982.2 KiB；168 DPI 冷光栅 223.39 ms、树缓存命中 53.09 ms。该页包含 2200 个实际内嵌字形，不再以系统宋体代替正文。

## 已执行的阶段

### P1 调度与状态

- 每次渲染分配请求序号；只有“最新请求 + 当前页 + 不降级”的结果可以替换画面。
- 过期结果仍写入缓存，但不会覆盖当前页，也不会改动全局 loading。
- 相同 `(page, dpi)` 的进行中请求会合并。
- 150 ms 防抖改为代际号实现的真正“最后一次操作后触发”。
- 缓存中若有更高 DPI 的同页位图，直接使用，避免降级重绘。

### P2 首屏与读取

- 新增 `page_size_only()`，只解析 `PhysicalBox`，不再为了尺寸统计所有对象。
- 打开文档时只同步解析第 1 页尺寸，其余页面在后台补齐；页面尺寸表先填元数据回退值。
- `Package::read_shared()` 对不超过 2 MiB 的条目做 16 MiB LRU 缓存，页面、模板、注释 XML 复用解压结果。
- 内部渲染 SVG 与自包含导出 SVG 分离；内部渲染跳过 `@font-face`。

### P3 缓存与缩略图

- 页面位图缓存改为 **128 MiB + 最多 8 张** 的字节预算 LRU。
- 命中缓存会更新顺序；当前显示页不会被刚插入的请求逐出。
- 缩略图从当前页向两侧扩展生成，优先满足附近页面。
- 缩略图仍串行执行，避免与首屏抢后台线程。

### P4 内部 SVG 精简

- `page_svg_for_render()` 不再写字体 Base64。
- 同一文本对象、同一基线的字符合并为一个 `<text x="x1 x2 ...">`，保留逐字定位。
- 用真实发票在 168 DPI 做像素对比：**1,286,214 个像素，0 差异**。
- 内部 SVG 从 145.5 KiB 降至 79.0 KiB，导出 SVG 从 236.0 KiB 降至 169.5 KiB。

## 相关决策

- 不通过提高 `opt-level` 或更换渲染后端获取速度。
- 优先消除重复工作、乱序覆盖和无效任务。屏幕光栅已改为 `DisplayList → tiny-skia` 直绘，`DisplayList → SVG → resvg` 保留为导出与 A/B 对照。
- 任何文本节点合并、内部 SVG 精简都必须通过像素级对比，不能只看耗时。
